# Opinionated Engineering

- Document ID: STD-001.1
- Status: Approved
- Version: 1.0
- Approved By: lead_architect (technical approval), product_owner (final acceptance)
- Approval Date: 2026-06-30

## Purpose

Extend STD-001 with an opinionated default posture: where a reasonable default
exists, ACEDP adopts one explicit, well-supported way of working rather than
leaving the choice open. This reduces decision overhead and keeps deliverables
consistent and reviewable.

## Scope

Applies to engineering and authoring choices within `acedp/`. It governs how
defaults are set and overridden. It does not mandate any specific platform,
vendor, or tool.

## Required Inputs

- The STD-001 baseline standards.
- A recurring decision for which a default would reduce ambiguity.

## Required Outputs

- A stated default, its rationale, and an explicit, documented escape hatch for
  justified exceptions.

## Review / Approval Rules

- Defaults are binding once approved; deviations require a recorded
  justification referencing this standard.
- New or changed defaults follow the Engineering Review process (SPEC-003).

## Principles

- Prefer one well-supported approach over several partially-supported ones.
- Make the implicit explicit; record assumptions rather than relying on them.
- Optimise for reviewability and reproducibility over local convenience.
- An exception is acceptable when documented; an undocumented deviation is not.
